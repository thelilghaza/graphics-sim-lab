================================================================================
BENCHMARK INTERPRETATION & AUDITED TECHNICAL ANALYSIS
================================================================================

1. **Primitive Intersection Reduction**:
   - For the 50+ sphere procedural scene, naive linear traversal executed 956,161,773 (956 million) sphere intersection tests.
   - BVH hierarchy reduced sphere tests to 20,773,480 (20.7 million) — an overall **46.03x reduction** in primitive sphere intersection tests.
   - BVH introduced 158,973,943 bounding-box slab tests to prune non-intersecting geometry branches.

2. **BVH Speedup vs Linear Traversal & Complexity Limits**:
   - On small scenes (5 objects), BVH incurs a slight overhead (~7% slower) because testing 5 spheres linearly (23.8M tests) is faster than traversing BVH tree nodes (18.6M sphere tests + 23.1M AABB tests).
   - On medium/large scenes (50+ objects), BVH provides a **2.47x single-threaded speedup** (2,164 ms vs 5,346 ms) in Release mode and **2.82x speedup** in Debug mode (15,229 ms vs 42,910 ms).
   - *Algorithmic Complexity Note*: On well-constructed hierarchies with minimal spatial overlap, BVH traversal exhibits typical $O(\log N \cdot R)$ average-case behavior per ray. In worst-case spatial arrangements with extensive box overlap, traversal degrades toward $O(N \cdot R)$ linear testing.

3. **Multithreaded Work Scaling & Parallel Synchronization**:
   - Thread parallelization is achieved via disjoint row range assignment per worker thread, using thread-local `RenderStats` accumulators with post-render aggregation and zero shared synchronization on the hot ray-tracing path.
   - Combining BVH acceleration with 16 worker threads reduced total procedural scene render time from 5,346 ms to **345.29 ms** — a **15.48x total performance acceleration factor** over the single-threaded naive baseline.

4. **Debug vs Release Compiler Optimization**:
   - Release build configuration (`/O2 /Ob2 /DNDEBUG`) produced **4.22x to 8.03x lower render times** than the Debug configuration (`/Od /RTC1`) across all tested workloads.
   - Inlining small vector methods (`Vec3`), stripping runtime check overhead, and optimizing tight slab ray-AABB loops likely account for this significant performance delta.
